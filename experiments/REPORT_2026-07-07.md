# SAMJAM 与 SceneGraphVLM 本地初测报告（2026-07-07）

## 1. 实验目标

本轮不是复现论文完整指标，而是回答两个面向周四汇报的问题：

1. SAMJAM 在真实/域外视频帧上暴露了哪些可观察问题？
2. SceneGraphVLM 官方 PVSG checkpoint 能否在本机运行，并直接作为“给定对象后只补关系”的后端？

## 2. 本机与运行方式

- GPU：NVIDIA GeForce RTX 3080 Ti Laptop，16GB 显存
- 驱动：566.07
- Python：3.10.20（独立 Conda 环境 `scenegraphvlm`）
- PyTorch：2.5.1+cu121
- Transformers：5.12.1
- ms-swift：4.4.0
- SceneGraphVLM checkpoint：官方 PVSG，约 2.21GB，Qwen3.5-0.8B
- 推理后端：Transformers，batch size 1，bfloat16，图像 640×480

由于本机没有 WSL/Docker，且官方镜像为 CUDA 13，本轮使用 Windows 原生 Transformers。Windows 无 vLLM、Flash Linear Attention 等论文加速路径，因此本报告中的耗时不能与论文的约 1 秒直接比较。

## 3. 测试输入

采用 SAMJAM 已经实跑过的同一组 4 帧 EPIC-KITCHENS 风格图像，内容包括桌面、盒子、碗/杯、瓶子、垫子和双手。原图 1368×768，SceneGraphVLM 输入统一缩放为 640×480。

这样做的目的，是让 SAMJAM 和 SceneGraphVLM 面对相同视觉内容，便于观察差异；本轮没有人工 ground truth，因此只报告结构指标和定性案例，不把它包装成准确率评测。

## 4. SAMJAM 已有输出审计

| 指标 | 本地 4 帧结果 |
|---|---:|
| 成功输出帧数 | 4/4 |
| 平均对象数/帧 | 10.50 |
| 平均关系数/帧 | 8.75 |
| 非法关系 ID 比例 | 0% |
| 相邻帧对象 ID Jaccard | 0.878 |
| 相邻帧关系 Jaccard | 0.785 |
| 同一 ID 出现多个名称 | 6 组 |

主要观察：

- ID 结构有效，但名称漂移明显：`box → carton → food box → box`、`table → wooden table`、`black mat → placemat → black mat`。
- 第 2/3 帧已经检测到左右手，但关系仍主要是 `ON/near`，没有稳定产生合理的手—物交互关系。
- 关系谓词存在大小写不一致，例如 `ON` 与 `near/NEAR` 混用。
- 因此 SAM2 的跟踪 ID 可以保留，但 Gemini 逐帧重新命名会污染节点语义，并可能让后续关系统计失真。

完整自动审计见 `experiments/samjam_audit/report.md`、`summary.json` 和 `frames.csv`。

## 5. SceneGraphVLM 端到端输出

| 指标 | SceneGraphVLM PVSG checkpoint |
|---|---:|
| 结构解析成功率 | 4/4（100%） |
| 平均对象数/帧 | 10.00 |
| 平均关系数/帧 | 1.25 |
| 关系端点 ID 合法率 | 100% |
| 平均生成耗时 | 9.01 秒/帧 |
| 4 帧关系总数 | 5 |

谓词分布：`on ×3`、`walking-on ×1`、`holding ×1`。

主要观察：

- 优点：TOON 格式四帧全部可解析，内部对象—关系 ID 没有悬空，输出比 SAMJAM 紧凑。
- 问题：小物体和动作关系召回很低，平均每帧只有 1.25 条关系。
- 首帧基本只输出 `table on floor`；这不是本场景最有价值的交互关系。
- 后两帧把双手区域识别为一个 `adult`，最后输出 `adult holding mat`；虽然出现 `holding`，但主客体语义错误。
- 多个框存在明显过大或重复，例如 `floor` 覆盖接近整幅图、两个 `adult` 框重复。

这与论文的限制一致：模型主要在 PSG/PVSG/Action Genome 闭集词表上训练，真实域外场景不能由数据集指标保证。

## 6. “已知对象 → 只生成关系”约束实验

将 SAMJAM 的对象 ID 和名称写进当前帧提示词，明确要求 SceneGraphVLM：

- 只能使用给定 ID；
- 不得重新生成对象表；
- 只输出 `rel[M]{subj,pred,obj}`。

| 指标 | 结果 |
|---|---:|
| 只输出关系的服从率 | 0/4（0%） |
| 使用给定 ID 的有效关系比例 | 0% |
| 格式不完整关系行 | 1 |
| 平均耗时 | 7.99 秒/帧 |

四帧均忽略了“只输出关系”的要求，继续自行生成对象、框和从 1 开始的新 ID。最后一帧甚至生成了缺少 object ID 的 `10,holding,`。

**结论：官方 checkpoint 不能仅靠 prompt 直接改造成 Grounded-SAM-2/SAMJAM 的关系后端。** 若要实现幻灯片中的架构，需要构造新任务数据并进行关系专用 SFT/LoRA；随后可用约束奖励或后处理禁止新 ID。

## 7. 当前可汇报结论

1. SAMJAM 的优势是开放词汇与较丰富关系，且 SAM2 能维持对象 ID；当前主要问题是逐帧类别名称漂移和关系语义噪声。
2. SceneGraphVLM 的优势是 TOON 格式稳定、关系紧凑、内部 ID 完整；但官方 PVSG checkpoint 在这组真实帧上关系召回低，并出现域偏移误判。
3. SceneGraphVLM 在论文数据集上优于 zero-shot Gemini，不等于它作为现成后端就优于 SAMJAM/Gemini。
4. 最关键的新发现是：SceneGraphVLM 的官方任务是“完整场景图生成”，不是“给定当前对象后补关系”；二者之间需要训练适配，而不是简单接线。
